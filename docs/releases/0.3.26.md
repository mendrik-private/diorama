# Diorama 0.3.26 release preparation

Prepared on 2026-09-30 from `main`, using `v0.3.25` as the previous release.
Before `v0.3.26` is created or pushed, the release owner must verify that the
successful GitHub Pages deployment is for the final main revision. The exact
revision, workflow run, and deployed
[`https://mendrik-private.github.io/diorama/`](https://mendrik-private.github.io/diorama/)
URL belong in the GitHub release notes, avoiding a self-referential commit that
changes the revision being verified.

## Change review

Every commit after `v0.3.25` and every release-bound working-tree change was
reviewed:

- `3bc857e` adds the screenshot-led user guide, its real-app captures, the
  documentation build and checks, and the Pages/release documentation gates.
- `ab3303d` changes Game Asset composition from multiplying line art inside the
  fill alpha to drawing black ink source-over the fill. Ink can now extend the
  generated silhouette, while off-white model paper remains transparent.
- `e6fddf6` expands the visual guide and normalizes its capture density.
- `827b1c0` preserves the Scale preview zoom selected before or during a slow
  method switch; Fit Pixels continues to refit replacement previews until the
  user zooms manually.
- `2052feb` renames vision.cpp/BiRefNet runtime overrides to
  `ASSET_SCALER_VISION_CLI`, `ASSET_SCALER_BIREFNET_MODEL`, and
  `ASSET_SCALER_BIREFNET_BACKEND`.
- The release-bound worktree adds real-app Bicubic/Game Asset comparisons for
  cave spider, goblin, and dragon originals at 128, 180, and 256 pixels, with
  source validation and capture provenance. It also prevents a freehand Pencil
  release coordinate from adding an unobserved straight tail after the last
  motion sample.

## Screenshot evidence and provenance

The established guide captures were made in the real Diorama application at
1280 × 800, display scale 1, GTK DPI 96, and are documented in
[`data/screenshots/guide/README.md`](../../data/screenshots/guide/README.md).
The captures at revision `ab3303d` already contain the current Game Asset ink
composition, so recreating them would not add release evidence.

The nine new comparison PNGs were captured on 2026-09-30 from the production
`Session::new` Game Asset path at source revision `2052feb`. The harness checks
the three original SHA-256 hashes before and after inference, uses default
Strength 40%, renders Bicubic on the left and Game Asset on the right, and
asserts 1280 × 800 output, equal panes, display scale 1, and 200% hard zoom.
All nine were reviewed at their native size and together at guide-thumbnail
size; titles, output dimensions, zoom, controls, and both images are readable
and unclipped. The originals and reproduction command are recorded beside the
captures. The screenshot lead independently reviewed all nine images.

The Pencil fix prevents an intermittent unwanted mark, and the Scale fix
preserves state across time. Their existing UI captures remain accurate; the
release uses deterministic graphical behavior tests as evidence for those
temporal and negative behaviors rather than staging a mock or synthetic
product screenshot.

## Release boundaries and remaining evidence

The physical input event that supplied the discontinuous release coordinate
was not captured. The deterministic graphical regression reproduces the exact
long-tail input-state failure and verifies committed document geometry. The
normal GTK motion path, fast/long strokes, click dots, shapes, and connected
lines are covered separately.

Repository-intelligence database and session files under
`.rust-repo-intelligence/` are local tooling state and are excluded from the
release. Release commit, push, Pages verification, tag creation, publication,
and Flatpak installation are intentionally outside this preparation step.
